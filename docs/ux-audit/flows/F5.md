# F5 — recovery: every error has a way out

Chromium 1440×900, demo + one stubbed 429; no server row written, the rejected
upload is a local text file. Evidence: `evidence/f5-recovery.json`,
screenshots `shots/f5-*.png`.

| # | Trigger | What the reader sees | Way out | Verified |
|---|---|---|---|---|
| A | wrong password | "Wrong email or password." in an alert; the address stays in the field | correct the two fields and submit | dashboard reached |
| B | expired reset link (`?token=demo-expired`) | "This link has expired." / "Request a new reset link to continue." | **Request a new link** | lands on `/forgot-password` |
| C | invalid reset link | "This link isn't valid." with the same sentence | **Request a new link** | lands on `/forgot-password` |
| D | PayPal return with no playground session | "Could not finish." — "This tab has no playground session. Start again from /playground." | **Back to the playground** | lands on `/playground` |
| E | non-zip upload | "Not a zip file — drop the deliverable zip." | the file input stays enabled; choose a zip | input enabled after the refusal |
| F | a payout row reads FAILED | FAILED chip and the retry control, `Retry payout for Icon Set` | **Retry payout** | row leaves FAILED after the retry |
| G | API answers 429 | "Could not load your settings." + the server's sentence, "Too many requests. Wait a moment." | **Retry** | the retry re-fires the request |

Friction:
- **1** — G prints the API's own message. It is readable here, but an
  unstructured upstream string is what will show when the message is not.
- **1** — E refuses without naming what it wants beyond "zip"; the accepted
  types are the input's `accept` attribute only.
- No dead end was found: each state names a next action, and the keyboard can
  reach it (the reset and return links are ordinary links; Retry is a button).

Not covered: a 500, a hanging request and a malformed body were not walked; the
429 path is representative of an API refusal but not of a hang.
