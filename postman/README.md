# Postman

Two files, both generated by `npm run gen:docs` (`scripts/gen-api-docs.mjs`) from
the same route table as `docs/openapi.json`:

- `VaultLance API.postman_collection.json` — 50 requests in 10 folders covering
  the real Express surface: Auth, Vaults, Audit, Invites, Payments, Files,
  Manifests, Ledger, Playground, Service.
- `VaultLance API.postman_environment.json` — `baseUrl` plus empty variables for
  `token`, `vaultId`, `fileId`, `orderId`, `approveUrl`, `resetToken`.

## Run it

1. Import both files and select the `VaultLance API` environment.
2. Set `baseUrl` to `http://localhost:3000/api` (or the deployed
   `https://vaultlance-ai.fly.dev/api`).
3. Run **Auth → POST /auth/register** then **POST /auth/login**. The collection
   stores the bearer token, and later folders pick up the vault and order ids from
   their own responses.
4. Payments folders call the VaultLance API, not PayPal directly; PayPal sandbox
   approval happens in the browser at the returned `approveUrl`.

## No secrets

The environment export contains names only. A `PAYPAL_CLIENT_ID` or
`PAYPAL_CLIENT_SECRET` pasted into Postman stays in your local Postman workspace;
nothing here needs them, because order creation and capture happen server-side.
